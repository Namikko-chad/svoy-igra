# Приложения (Android, Windows, Linux, macOS)

Одно Flutter-приложение в `clients/`, которое собирается для Android-телефонов и для компьютеров
на Windows, Linux и macOS. Каждая сборка умеет то же, что и веб-клиент: создание игр и вход в них;
роли игрока, ведущего, админа (библиотека паков, полноценный редактор паков, импорт/экспорт файла
игры) и экрана. Оно открывает ссылки-приглашения. Правила проекта находятся в `clients/CLAUDE.md`.

## Платформы

| | Android | Windows | Linux | macOS |
|---|---|---|---|---|
| `hello.platform` | `android` | `windows` | `linux` | `macos` |
| Видео | `video_player` | `fvp` (libmdk) | `fvp` (libmdk) | `video_player` (AVFoundation) |
| Аватар | галерея или камера | файл картинки | файл картинки | файл картинки |
| Кнопка «Поделиться» | системное меню | системное меню | — (только копирование) | системное меню |
| `svoyigra://` | манифест | регистрируется при запуске (текущий пользователь) | регистрируется при запуске (файл `.desktop`) | `Info.plist` |
| `https://…/g/<PIN>` | App Links | — | — | — |

Отличия десктопа собраны в платформенном слое:

- `lib/core/platform.dart` (`clientPlatform`, `isDesktop`) — единственный переключатель; в текстах
  про устройство вместо «телефон» стоит «компьютер», в меню аватара вместо галереи и камеры —
  выбор файла.
- `lib/data/device.dart` заполняет `hello` для каждой ОС: Windows — имя компьютера и редакция
  (сборка 22000+ показывается как Windows 11); Linux — производитель и модель из DMI и название
  дистрибутива; macOS — модель и версия. `screen` — размер дисплея.
- `lib/data/url_scheme.dart` регистрирует `svoyigra://` при каждом запуске — для текущего
  пользователя и для последней запущенной копии: Windows пишет `HKCU\Software\Classes\svoyigra`;
  Linux пишет `~/.local/share/applications/dev.svoyigra.client.desktop` (пункт меню с иконкой)
  и вызывает `xdg-mime default`. macOS объявляет схему в `Info.plist`.
- Один экземпляр: ссылка, открытая при запущенном приложении, передаётся в открытое окно
  (Windows: `SendAppLink` в `windows/runner/main.cpp`; Linux: уникальный `GApplication` в
  `linux/runner/my_application.cc`; macOS делает это сама). На Linux ссылка, с которой
  приложение запущено, приходит первым аргументом `main`.
- Окно: заголовок «Своя игра», 1280 × 800 при запуске, не меньше 400 × 560 (телефонная раскладка
  по-прежнему работает). macOS работает в песочнице с правами сетевого клиента/сервера (UDP-поиск)
  и доступа к выбранным пользователем файлам; `NSAllowsArbitraryLoads` разрешает медиа по HTTP в LAN.
- Android-APK не включает нативные библиотеки `fvp` (`android/app/build.gradle.kts`).


## Сценарий

1. **Сервер** — приложение рассылает широковещательный запрос обнаружения (UDP 3051, повторяется каждые 700 мс
   в течение 2,5 с), показывает найденные и недавно использованные серверы и принимает введённый вручную адрес. Каждый
   адрес проверяется через `GET /api/info`.
2. **Игра** — на экране сервера:
   - «Мои игры»: места, которые это устройство занимает на этом сервере (проверяются через `/api/auth/me`;
     недействительные забываются);
   - «Игры на сервере»: текущие игры (`GET /api/games`, без PIN) — предлагается только «Смотреть»
     (экран без PIN); чтобы играть, нужен PIN от админа;
   - «Войти в игру»: 6-значный PIN игры;
   - «Создать игру»: необязательное название и PIN админа (4–8 цифр, вводится дважды) → экран
     админа новой игры.
3. **Роль** — карточка игры, «Продолжить как …», затем Игрок (имя), Ведущий (недоступно, пока
   занято), Экран, Администратор (PIN админа).
4. **Сессия** — один WebSocket на экран (`GameSocket`). «Выйти» отправляет `leave` (игрок
   сначала подтверждает: место и очки удаляются) и забывает токен; системная кнопка «Назад»
   только закрывает экран. Коды закрытия `4001`/`4003`/`4004` забывают токен и
   возвращают назад с сообщением («Игра закрыта» для `4004`); `4009` предлагает «Продолжить здесь».

## Ссылки-приглашения

- `svoyigra://join?server=<base>&pin=<PIN>` — обрабатывается всегда (веб-страница `/g/<PIN>`
  предлагает её на Android как «Открыть в приложении»).
- `http(s)://<APP_LINK_HOST>/g/<PIN>` — Android App Links, хост фиксируется при сборке:
  `make build-apk APP_LINK_HOST=igra.example.com`. Если он не задан, фильтр использует хост
  `app-links.invalid`, который никогда не совпадает. `make cert-sha256` выводит отпечаток
  debug-ключа для `ANDROID_CERT_SHA256` на сервере.

Ссылка открывает шаг выбора роли для этого сервера и игры (`app_links`, разбор в
`lib/data/deeplink.dart`).

## Экраны

| Роль | Экран |
|---|---|
| Игрок | таблица очков, табло (нажимается в мой ход), блоки вопроса, полоса таймера, кнопка, ввод ответа, показ ответа, итоги раунда/финала; в альбомной ориентации используется боковая панель |
| Ведущий | вкладки **Игра** (старт, когда админ загрузил пак, все команды ведущего, ответ + комментарий всегда видны, панель оценки, введённый ответ, выбор выбирающего/удаление для каждого игрока, раунды, сброс) и **Настройки** (таймеры, штраф) |
| Админ | вкладки **Игра** (PIN, ссылка-приглашение с копированием / системным меню «Поделиться» / QR, фаза, статус ведущего, выбор пака, все настройки, включая компенсацию задержки, экспорт/импорт файла игры, переименование, PIN админа, сброс, закрытие игры), **Игроки** (очки ±100 / произвольно / задать, RTT последний/средний/джиттер с раскраской по шкале задержки, последняя активность, сдвиг кнопки −5000…10000 мс и эффективный сдвиг, статистика, устройство, удаление), **Пакеты** (библиотека: создание, импорт `.dub`, экспорт, удаление, блокировка, «Редактировать копию» для заблокированных паков) |
| Редактор паков | метаданные; раунды → категории (≤ 10, предупреждение при ≠ 10) → вопросы; перетаскивание для переупорядочивания; форма вопроса со стоимостью, переопределением времени чтения, полями markdown с живым предпросмотром; менеджер медиа (загрузка из галереи/аудио/любого файла с прогрессом, предпросмотр, удаление, вставка в позицию курсора); баннер для заблокированных паков |
| Экран | отображение только для чтения; видео и аудио воспроизводятся автоматически со звуком; лобби с PIN, ссылкой и QR |

## Специальные вопросы и финал

`features/game/special.dart` показывает заставку модификатора, передачу кота и аукцион
(сумма с шагом ±100, «Ставка», «Ва-банк», «Пас»); `features/game/final_panel.dart` охватывает
удаление тем, ставки, письменный ответ на время и оценку. Ведущий действует от имени
выбирающего или убирающего и закрывает торги, ставки и ответы. В соло-вопросах кнопка не показывается.
В редакторе паков у каждого раунда есть переключатель «Финал» (один вопрос на тему, без стоимости) и
панель инструментов markdown (`features/editor/markdown_format.dart`) с «Медиа» в каждом поле.

## Медиа

Изображения через `Image.network`; видео через `video_player` — на Windows и Linux через `fvp`,
который подключается автоматически (игроки: автовоспроизведение без звука, ведущий:
элементы управления, экран: автовоспроизведение со звуком); аудио через `audioplayers` (игроки: плашка «звучит на
экране» с ручным воспроизведением). Markdown через `flutter_markdown_plus` (CommonMark; сырой
HTML показывается как текст). К относительным URL добавляется адрес сервера.

## Сборка

```bash
make -C clients analyze test
make -C clients build-apk-debug   # build/app/outputs/flutter-apk/app-debug.apk
make -C clients build-apk         # release APK, подписан debug-ключом
make -C clients build-apk APP_LINK_HOST=igra.example.com
make -C clients build-linux       # build/linux/x64/release/bundle/svoy_igra
make -C clients build-windows     # build\windows\x64\runner\Release\svoy_igra.exe
make -C clients build-macos       # build/macos/Build/Products/Release/SvoyIgra.app
make -C clients run DEVICE=linux  # или windows / macos / id Android-устройства
```

Каждая десктопная сборка делается на своей ОС: Flutter не собирает десктоп под другую систему.
GitHub Actions собирает их все и оба APK за один запуск (`.github/workflows/builds.yml`,
см. [Начало работы](03-getting-started.md#сборки-на-github-actions)).
Что нужно: Linux — `clang`, `cmake`, `ninja`, dev-пакеты GTK 3 и GStreamer (`fvp` скачивает libmdk
при сборке); Windows — Visual Studio 2022 с «Desktop development with C++»; macOS — Xcode.
Распространяйте папку сборки целиком (Linux, Windows) или `.app` (macOS); десктопные сборки не подписаны.

Id Android-приложения `dev.svoyigra.mobile` (оставлен, чтобы установленные телефоны обновлялись);
id десктопа `dev.svoyigra.client`. Незашифрованный HTTP разрешён (серверы в LAN). Шрифты включены в сборку.
