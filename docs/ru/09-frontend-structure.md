# Структура веб-клиента

Vue 3 (`<script setup lang="ts">`) + Vite + TypeScript + vue-router + Pinia, `markdown-it`
(`html: false`, `linkify`), `qrcode-generator` для QR-кода входа. Без UI-фреймворка: дизайн-система —
это пользовательские свойства CSS плюс собственные компоненты. Правила: `frontend/CLAUDE.md`.

## Маршруты

| Путь | Страница | Кто |
|---|---|---|
| `/` | создание игры (PIN админа + подтверждение, необязательное название) или ввод PIN игры; игры, для которых в этом браузере есть токены | все |
| `/g/:pin` | шаг выбора роли: название игры/пак/игроки, Игрок (имя) / Ведущий (недоступно, пока занято) / Экран / Администратор (PIN админа); «Продолжить как …»; «Открыть в приложении» на Android | все |
| `/g/:pin/play` | таблица очков, табло, вопрос, кнопка, ввод ответа, показ ответа, итоги | игрок |
| `/g/:pin/host` | старт игры (после того как админ загрузит пак), ведение игры, оценка, таймеры, сброс | ведущий |
| `/g/:pin/admin` | карточка-приглашение (PIN, ссылка, копирование, QR, Web Share), переименование / PIN админа, выбор пака, настройки, файл игры, таблица игроков, сброс, закрытие игры | админ |
| `/g/:pin/admin/packs` | общая библиотека: создание, импорт `.dub` с индикатором прогресса, экспорт, удаление, блокировка, «Редактировать копию» для заблокированных паков | админ |
| `/g/:pin/admin/packs/:id` | редактор пака: раунды, категории, вопросы, живой предпросмотр, менеджер медиа (уведомление «только для чтения» для заблокированных паков) | админ |
| `/g/:pin/screen` | вид для большого экрана, оверлей «включить звук», двойной клик = полный экран, лобби со ссылкой, QR и PIN | экран |

Все страницы игры используют общий `GameShell` (верхняя панель с PIN и «Выйти» = `leave`) и
`useRoleSocket` (4001 → назад к шагу выбора роли, 4004 → «Игра закрыта», 4003 — удалён,
4009 — открыто в другом месте). Страница без сохранённого токена переходит на `/g/:pin`.

## Структура

```
src/
  main.ts, App.vue, router.ts
  types/protocol.ts        типы протокола из docs/en/05-protocol.md (+ normalizeView)
  api/http.ts              обёртка над fetch: Bearer, {error:{code,message}} → ApiError
  api/transfer.ts          XHR-загрузки с прогрессом, аутентифицированные скачивания blob
                           (имя файла из Content-Disposition filename / filename*)
  api/index.ts             эндпоинты
  ws/client.ts             GameSocket: hello, ping→pong, переподключение 1…10 с, смещение часов,
                           коды закрытия 4001/4003/4009 останавливают переподключение
  composables/             useGameSocket (ошибки → тосты, звуковые сигналы), useNow,
                           useQuestionTimer, useHostAuth
  stores/                  session (токены в localStorage), toast
  utils/                   blocks (разбиение из §3), markdown, time, latency, device,
                           mediaName (транслитерация), sound (тоны WebAudio), reorder
  components/              GameBoard, BuzzerButton, TimerBar, Scoreboard, QuestionBlocks,
                           MediaBlock, Standings, QrCode, диалоги, тосты
    host/ admin/ editor/   панели для конкретных ролей
  pages/                   один файл на маршрут
  styles/tokens.css        токены DESIGN_MANIFEST.md; base.css
tests/                     модульные тесты разбиения и клиента (Vitest)
```

## Заметки о поведении

- Специальные вопросы и финал: `components/special/SpecialStage.vue` отображает
  `cat_transfer`, `auction` и каждую фазу `final_*` для каждой роли (действия игрока, действия ведущего
  от чужого имени, экран только для чтения); полноэкранная заставка объявляет модификатор, когда
  открывается специальная ячейка. Чистая логика представления находится в `utils/special.ts`.
- Поля markdown редактора паков используют `components/editor/MarkdownField.vue`: панель инструментов (жирный,
  курсив, заголовок, списки, цитата, ссылка, выбор/загрузка «Медиа») поверх `utils/mdEdit.ts`;
  живой предпросмотр воспроизводит медиа. Раунд можно переключить на «Финал».
- Токены: ключ `localStorage` `svoy.token|<origin>|<pin>|<role>`, проверяется через `/api/auth/me`
  перед тем, как предложить «Продолжить как …».
- Полосы таймера: чтение `readingStartsAt → readingEndsAt`, затем `buzzStartsAt → buzzEndsAt`,
  по часам сервера.
- Загрузка медиа отправляет очищенное латинское поле `name` перед `file`.
- Dev-сервер слушает `0.0.0.0:${FRONTEND_PORT:-3000}` и проксирует `/api` (включая
  WebSocket) и `/.well-known/` на `${BACKEND_URL:-http://localhost:3050}`, сохраняя
  браузерный `Host` и добавляя `X-Forwarded-*`, чтобы ссылки-приглашения указывали на веб-клиент.
- Продакшен: `pnpm build` → `dist/`, раздаётся бэкендом (`STATIC_DIR`) с того же адреса,
  что и API, — корневой `Dockerfile` собирает всё в один образ. Обратный прокси перед ним
  должен пропускать `Host`/`X-Forwarded-Host` и апгрейд до WebSocket.
