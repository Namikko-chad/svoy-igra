# Структура бэкенда

```
backend/
  main.go                 config.Load → app.Run; SIGINT/SIGTERM → корректная остановка;
                          команды оператора `svoy-igra unlock-pack <id>`, `svoy-igra healthcheck`
  app/server.go           build() связывает компоненты; start() запускает циклы; Run() обслуживает запросы
  app/server_test.go      полная игра по настоящим HTTP + WebSocket
  app/config/             конфигурация из окружения, Version
  app/httpx/              JSON-хелперы, тип ошибки и политика ошибок
  app/ids/                случайные id, токены, PIN
  app/packs/              библиотека паков
    store.go              каталог библиотеки, SQLite-подключение на пак, создание/удаление/список, блокировка
    tree.go               типы, полное дерево, CRUD + переупорядочивание раундов/категорий/вопросов
    media.go              имена медиа, MIME, сохранение/удаление
    archive.go            экспорт .dub (VACUUM INTO + zip), импорт (распаковка с проверкой), копирование
    blocks.go             SplitBlocks: markdown вопроса → блоки text/image/video/audio
  app/game/               игры
    manager.go            все игры: создание, поиск по PIN/токену, цикл сохранения, удаление простаивающих
    identity.go           PIN игры, PIN админа, токены ролей, слот ведущего, присутствие, leave/close
    types.go              фазы, настройки, игроки, история, файл игры, представления
    engine.go             дисциплина блокировок/хуков, игроки, таймеры, механика вопроса
    commands.go           команды игрока/ведущего/админа
    special.go            модификаторы: случайная расстановка, кот, аукцион, соло-ответы
    final.go              финальный раунд: финалисты, удаление тем, ставки, письменные ответы, оценка
    avatar.go             аватары игроков/ведущего: установка, удаление (модерация админом), URL, очистка файлов
    view.go               представления, отфильтрованные по ролям
    persist.go            запись games/<id>.json (идентичность + содержимое), экспорт/импорт, восстановление
  app/ws/hub.go           аутентификация сокетов, циклы чтения/записи, ping/pong, рассылка
  app/api/api.go          REST-обработчики
  app/discovery/          UDP-ответчик обнаружения
```

## Пакеты

**httpx.** `Error{Status, Code, Message}` — ошибка, которую клиент может исправить; `Fail` записывает её
как `{"error":{code,message}}`. Любая другая ошибка логируется, а в ответ отдаётся непрозрачная
`500 internal_error`.

**ids.** Токены — 16 случайных байт в hex; PIN игр — 6 цифр (уникальны среди текущих
игр); PIN админа хранятся как SHA-256 с солью. Неверный PIN админа стоит 500 мс.

**packs.** Каждый пак — это каталог `DATA_DIR/packs/<12-hex id>/` с `pack.sqlite` и
`media/`. У каждой базы данных пака одно кэшированное подключение с включёнными внешними ключами. Позиции
перенумеровываются `0..n-1` после каждого перемещения или удаления. В раунде не более 10 категорий.
`rounds.kind` (`normal`/`final`) добавляется в старые файлы паков при открытии; финальная тема содержит
ровно один вопрос (`409 final_one_question`).
Пак с `meta.locked = '1'` отклоняет любое изменение и удаление (`409 pack_locked`);
`Copy` дублирует базу данных и медиа в новый разблокированный пак.
Импорт принимает только `pack.sqlite` и `media/<valid name>`, проверяет общий распакованный
размер, проверяет `meta.format_version = 1` и таблицы и удаляет всё при любой
ошибке. Экспорт делает снимок базы данных через `VACUUM INTO` и хранит медиа без сжатия.

**game.** Правила движка см. в `backend/CLAUDE.md`. Экраны бывают двух видов: вошедшие
по PIN (`screenTokens`) и наблюдающие из публичного списка (`watchTokens`); хаб
помечает сокет наблюдателя как `limited`, и тогда `View`/`info` не включают PIN и ссылку. Слот ведущего удерживается, пока
сокет использует токен ведущего, и в течение 30 с после его отключения; `leave` освобождает его сразу.
Присутствие учитывает каждый сокет игры; когда оно достигает 0, запускается отсчёт простоя.
Важные детали:
- игрок, присоединившийся во время вопроса, получает кнопку для текущего окна;
- удаление (kick) отвечающего игрока заново открывает кнопки для остальных;
- `reset_game` без `keepPlayers` отзывает все токены игроков (сокеты закрываются с кодом `4001`);
- `close_game` и удаление по простою удаляют файл игры и закрывают её сокеты с кодом `4004`;
- импорт игры сохраняет сокеты игроков, чьи id и токен не изменились, и
  закрывает остальные с кодом `4001`.

**Временные файлы.** Загрузки и экспорт собираются в `DATA_DIR/tmp` (`Config.TempDir`), а не
во временном каталоге системы — в образе контейнера его нет. Каталог очищается при старте.

**Аватары.** `POST /api/avatar` определяет формат по байтам (PNG/JPEG/WebP/GIF, ≤ 2 МиБ) и записывает
`DATA_DIR/avatars/<gameId>/<random>.<ext>`; новая загрузка или удаление стирает предыдущий файл,
выход игрока из игры удаляет его файл, а закрытие игры удаляет весь каталог. Файлы
раздаются с заголовком неизменяемого кэша (immutable), потому что имена меняются при каждой загрузке.

**ws.** Токен из `/api/ws?token=` определяет игру и роль. Одно живое подключение на токен
игрока и на токен ведущего (более новое закрывает старое с кодом `4009`). Пинги каждые
2 с; три пинга без ответа помечают игрока отключённым до следующего pong. Изменения,
касающиеся только админов (RTT, информация об устройстве), перерисовывают только сокеты админов.

**discovery.** Отвечает на датаграмму `SVOY_IGRA_DISCOVER` сообщением
`{"name","port","version"}`.
